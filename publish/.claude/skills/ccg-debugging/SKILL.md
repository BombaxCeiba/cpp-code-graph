# ccg 调试溯源组合拳

调试的核心动作是**验证连通性**：症状出现的位置和 suspected 根因之间，调用图上到底有没有路、经过谁。ccg 的 trace/callers/changes 三件套把这个验证变成可重复的命令。

## 何时使用

- "为什么 X 会崩 / 这个错误从哪来"
- "帮我追这个 bug"
- 怀疑某次改动引入回归，想圈定嫌疑面

## 前置检查

1. `ccg stats` 确认 db 存在（没有则先走 `ccg-index`；调试旧版本代码时注意 db 是否对应当前源码——不确定就 `ccg update` 或重索引）。
2. 手里有至少一个"症状符号"（崩溃点/报错抛出处/错误状态写入处）。
3. 有或能猜出"根因候选符号"（最近改过的、可疑的函数/类）。

## 组合拳剧本

### 第 1 步：两端 trace，验证连通性

```
ccg trace <症状符号> <根因候选>
ccg trace <根因候选> <症状符号>      # 反方向也要跑
```

- trace 是 calls + confidence ≥ 0.7 的 virtual_dispatch 边的最短路（每符号最短深度；上限 10 跳）。动态派发证据默认开启，`--no-dispatch` 回到纯静态 calls；0.4 弱推断低于阈值，不参与寻路。
- **找到路径** → 逐跳 `--calls-->` 链就是传播通道，逐跳读代码找坏点。
- **不通**（`no path ... within 10 hops`，退出码 1）→ 两层含义：(a) 中间隔了未解析目标（函数指针/虚分发/回调注册），(b) 确实无调用链（问题不在调用层，查数据/状态/并发）。两种都要落到源码确认，不要断言"绝无关联"。
- 端点本身解析不了（拼写/歧义）也是退出码 1——先回 `ccg query` 修正坐标，配合 `--kind/--file` 消歧。

### 第 2 步：callers 逆流而上，圈定入口

```
ccg callers <症状符号> --depth 2
```

从崩溃点逆流向调用者分层展开（行尾 `(via ...)` 溯源），找到真实入口（main/消息循环/测试体），确认"谁在什么路径上触发了它"。零调用者消息是**风险信号**：未使用，或仅经未解析目标调用——后者正是 trace 不通时的常见原因。

### 第 3 步：context 看清两端的结构

```
ccg context <符号> [--json]
```

incoming/outgoing 全边一览：谁 uses 它、它 overrides/extends 谁、代表调用点在哪。虚方法默认合并 override 家族——崩溃栈里看到的是哪个具体实现，用 `--no-merge` 分开查。有动态证据的调用点标 `[dispatch 0.70]`；无证据的家族估算标 `[dispatch unknown · family estimate]`（动态类型无法证明，按整个 override 家族估算，可能包含并非实际目标的实现）。需要连 0.4/0.0 的家族估算标记一起看时加 `--dispatch-fallback`——它只做标注（`context` 额外列出低于阈值的边），不改变归属集合。

### 第 4 步：changes 圈定嫌疑面（回归场景）

```
ccg changes <最近改动的文件>... [--depth N] [--json]
```

- 把最近编辑过的文件喂进去（装了 hook 的项目可参考每次编辑注入的 `[ccg] 已入库 ...；受影响符号 N ...` 摘要行快速定位）。
- 消费者列表 = 被波及符号及其风险档；症状符号若出现在消费者里，嫌疑直接坐实；没出现也说明波及面在哪，指导下一步看哪。
- 文件状态三态（present/deleted/unknown）都不静默丢；删除文件的影响要在下次 index 前查才可见。

## 解读规则

- **路径优先于猜测**：trace 给出的每一跳都有调用点坐标，逐跳读源码确认，不要跳步。
- **不通是信息不是失败**：排除调用层后，转向数据流/状态机/并发假设。
- **风险档位**（LOW≤8<MEDIUM≤30<HIGH≤120<CRITICAL，score=3*direct+transitive+fan_in）用于排优先级，不替代阅读。
- truncated: yes = --depth 用尽（扩展截断），退出码 0、计数完整。

## 常见坑

- **db 过期**：源码已改而 db 未刷，trace/callers 会指向旧行号——先 `ccg update`（装 hook 的项目基本免疫）。
- **未解析边**：函数指针、注册回调、动态分发在图里没有 calls 边；trace 不通时优先怀疑这些位置。
- **表格长路径列溢出**是显示 nit，坐标仍可读；机器分析用 `--json`。
- 同 kind 同文件的重载当前无法用 --kind/--file 消歧——用 query 拿坐标，或换符号。

## Checklist

- [ ] db 存在且新鲜（`ccg update` 过或 hook 常新）
- [ ] 症状符号与根因候选各就各位（query 消歧过）
- [ ] trace 双向都跑过，结论区分"有路径/无路径/未解析中断"
- [ ] callers 找到真实入口
- [ ] 回归场景用 changes 圈过嫌疑面
- [ ] 每个结论附符号 file:line 坐标

## 边界

- ccg 只看结构（调用/继承/使用），不做数据流分析；"值从哪来"要回源码。
- 图只覆盖索引过的 TU；库外与未解析目标天然缺席。
- 不发明命令或旗标；用法疑问查 `ccg help trace` 等。
